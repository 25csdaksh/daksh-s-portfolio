React.js — Full Short Notes

A complete, beginner-friendly reference for revision: JSX, components, props, state, hooks, and app architecture — with a plain-English explanation before every code block.

01

What is React

In plain terms: React is a JavaScript library (created by Facebook/Meta) for building user interfaces out of small, reusable pieces called components. Instead of manually updating the DOM when data changes, you describe what the UI should look like for a given state, and React updates the screen for you.
  • Component-based — UI is broken into small, independent, reusable pieces
  • Declarative — you describe the "what", React handles the "how"
  • Virtual DOM — React compares a lightweight in-memory tree to the real DOM and updates only what changed
  • Unidirectional data flow — data flows one way: parent → child, via props
02

JSX — JavaScript XML

JSX lets you write HTML-like markup directly inside JavaScript. It's not valid JS on its own — a build tool (Babel) compiles it into plain React.createElement() calls behind the scenes.
const element = (
  <h1>Hello, {name}</h1>   // {} embeds any JS expression
);
Every JSX block must return a single root element — wrap multiple elements in a <div> or a fragment <>...</>.
03

Components

A component is just a JavaScript function that returns JSX describing part of the UI. Modern React uses function components almost exclusively — the older class-based style still works but is rarely used in new code.
function Welcome() {
  return <h1>Hello there</h1>;
}

// used like a custom HTML tag:
<Welcome />
04

Props — properties

Props pass data from a parent component into a child component — like function arguments. They're read-only: a component must never modify its own props.
function Greeting(props) {
  return <h1>Hello, {props.name}</h1>;
}

<Greeting name="Sam" />   // passes name="Sam" as a prop
05

State — useState

State is data that a component owns and that can change over time. Updating state with the setter function tells React to re-render the component with the new value — you never mutate state directly.
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);  // [current value, setter]

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}
06

Event Handling

React events are named in camelCase (onClick, not onclick) and are passed a function reference — not a string like in plain HTML.
function handleClick() {
  console.log('clicked!');
}

<button onClick={handleClick}>Click me</button>
07

Conditional Rendering

Since JSX is just JavaScript, you show/hide UI using normal JS logic — ternaries, &&, or early returns — instead of template-specific directives.
{isLoggedIn ? <p>Welcome back</p> : <p>Please log in</p>}

{hasError && <p>Something went wrong</p>}  // renders only if hasError is true
08

Lists & Keys

.map() turns an array of data into an array of JSX elements. Each item needs a unique key prop so React can efficiently track which items changed, were added, or removed.
const fruits = ['apple', 'banana', 'cherry'];

<ul>
  {fruits.map((fruit) => (
    <li key={fruit}>{fruit}</li>
  ))}
</ul>
Avoid using array index as key if the list can reorder — it confuses React's diffing and can cause bugs.
09

Forms & Controlled Inputs

In a "controlled" input, the input's value is driven by React state — every keystroke updates state, and state drives what's displayed. This keeps the form's data in sync with your component.
function NameForm() {
  const [name, setName] = useState('');

  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
    />
  );
}
10

useEffect

Runs "side effects" — code that reaches outside React, like fetching data, subscriptions, or manually touching the DOM — after render. The dependency array controls when it re-runs.
import { useEffect } from 'react';

useEffect(() => {
  console.log('ran after render');
}, [count]);  // re-runs only when `count` changes

// [] → runs once on mount   |   no array → runs after every render
11

useRef

Creates a mutable value that persists across renders without causing a re-render when changed. Most commonly used to directly access a DOM element.
const inputRef = useRef(null);

function focusInput() {
  inputRef.current.focus();   // .current holds the actual DOM node
}

<input ref={inputRef} />
12

useMemo & useCallback

Both are performance tools that skip unnecessary recalculation. useMemo caches a computed value; useCallback caches a function so it isn't recreated on every render.
const total = useMemo(() => expensiveSum(items), [items]);

const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);
Only reach for these once you've actually measured a performance problem — overusing them adds complexity for little benefit.
13

useContext

Lets deeply nested components read shared data (like a logged-in user or theme) without manually passing props down through every level in between — known as "prop drilling."
const ThemeContext = createContext('light');

// provide it high up in the tree:
<ThemeContext.Provider value="dark">
  <App />
</ThemeContext.Provider>

// read it anywhere below, no prop passing needed:
const theme = useContext(ThemeContext);
14

Custom Hooks

A custom hook is just a regular function, prefixed with use, that calls other hooks inside it — used to extract and reuse stateful logic between components.
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handler = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handler);
    return () => window.removeEventListener('resize', handler);  // cleanup
  }, []);

  return width;
}
15

Lifting State Up

When two sibling components need to share the same data, move that state up to their nearest common parent, then pass it down as props. This keeps a single source of truth.
parent
owns the state
child A
reads via props
child B
updates via callback prop
16

Component Composition

React favors composition over inheritance — build complex UIs by nesting and combining small components, often passing JSX itself as a prop via children.
function Card({ children }) {
  return <div className="card">{children}</div>;
}

<Card>
  <h2>Title</h2>   // this becomes Card's `children` prop
</Card>
17

React Router — basics

React itself doesn't include page routing. react-router-dom is the standard library for building multi-page navigation in a single-page app without full page reloads.
import { BrowserRouter, Routes, Route } from 'react-router-dom';

<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/about" element={<About />} />
  </Routes>
</BrowserRouter>

Lifecycle — class-component era

Older React used class components with named lifecycle methods. Function components replace all of these with useEffect, but you'll still see this style in older codebases.

componentDidMountuseEffect(fn, [])
componentDidUpdateuseEffect(fn, [dep])
componentWillUnmountthe function useEffect returns

20

Best Practices

  • Keep components small and focused on one responsibility
  • Never mutate state directly — always use the setter function
  • Always give list items a stable, unique key
  • Clean up subscriptions/timers inside useEffect's return function
  • Lift state up only as far as necessary — don't over-centralize
  • Name custom hooks starting with use so React can enforce hook rules
